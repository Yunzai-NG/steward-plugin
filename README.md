# @yunzai-ng/steward-plugin

指令运维：在聊天里重启实例、更新插件、更新内核。全部命令限**主人**。

> 需要 **core ≥ 0.6.1** —— 用到了那一版新增的 `ctx.app.maintenance`（受控地更新插件与请求重启）。

## 命令

| 命令 | 作用 |
|---|---|
| `#重启`（`#重启内核` / `#重启实例`） | 优雅停机，由外部守护拉起 |
| `#更新插件 [名字…]` | 更新指定插件并重载；不写名字则更新全部（本插件自己除外） |
| `#更新自己` | 更新本插件；更新后需重载或重启才生效 |
| `#更新内核`（`#升级内核`） | 经包管理器把内核升到目标版本，之后重启才生效 |
| `#运维状态` | 看这台实例能不能重启、装了几个插件 |

`#更新插件 a b c` 逐个更新点名的几个；写错名字会得到内核那句「没有名为 X 的插件」，不静默跳过。

## 关于「重启」——先读这段

**内核自己没有重启能力。** 它能做的是「优雅停机」，把进程停干净;**再把它拉起来这一步，得靠外部守护**（pm2 / systemd / Windows 服务）。所以：

- 装了守护：`#重启` 停机后，守护看到进程退出（退出码 75）即拉起，十几秒后回来。
- 没有守护（裸 `node` 起的）：`#重启` **不会停机**，只回一句「这台实例没有守护接管，请手动重启」。停一个没守护的实例等于把机器人关掉再也起不来，本插件不会那么做。

能不能重启由内核的 `maintenance.canRestart` 判定（有没有人接管过重启），确定无误;探测到的守护类型（pm2 / systemd）只用来把话说得更准，探测不到**不代表**没有守护（Windows 服务不留痕迹）。

### pm2 / systemd 示例

pm2 默认 `autorestart`，退出即拉起，无需额外配置。但 pm2 之下**没有 TTY，标准输入适配器用不了**，托管前先禁用它。

systemd 单元建议 `Restart=always`（`on-failure` 也行，退出码 75 非零，会拉起）：

```ini
[Service]
Restart=always
Environment=YZNG_HOME=/home/yunzai
ExecStart=/usr/bin/yzng start
```

`YZNG_HOME` 必填 —— 以服务或 pm2 启动时工作目录不是项目目录。

## 更新内核

`#更新内核` 代跑一次 `yzng update`（不自己重写升级逻辑：那条命令里攒着「只升 cli、其余由它带上来」「剪掉根 package.json 里多余的框架依赖」等一串只有踩过才知道的判断）。装好后**必须重启才生效**——新内核代码不能热替换进正在跑的进程。若此时重启不可用，会明说「现在跑的仍是旧内核」。

目标版本在配置里填，只收 dist-tag（`latest`）或具体版本号（`0.6.1`），**不收 `^0.6.0` 这类范围**——那些符号在命令行里另有含义。

## 配置

| 项 | 缺省 | 说明 |
|---|---|---|
| 允许指令重启 | 开 | 关掉后 `#重启` 只回说明、不动实例 |
| 撞上本地改动时 | 停手不改 | 插件目录有未提交改动时：停手 / 暂存 / 丢弃 |
| 更新后装依赖 | 开 | package.json 变过时必须装 |
| 更新后自动重载 | 开 | 关掉则要去面板插件页手动重载 |
| 内核目标版本 | latest | dist-tag 或具体版本号 |
| 内核更新超时 | 15m | 国内网络冷装十几分钟不罕见 |
| 更新内核后自动重启 | 开 | 关掉则更新完只提示，自己决定何时重启 |
